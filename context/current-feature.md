Added `bcryptjs`. The script is idempotent — system types are matched on `[name, userId: null]` and the demo user's collections/items are cleared and rebuilt on each run. Extended `scripts/test-db.ts` to fetch the seeded data back, assert the demo user, collection names and item counts, per-contentType content and collection membership, then print it all as a tree. Verified across two consecutive seed runs (5 collections / 18 items / 18 join rows, no duplicates); build, lint, and db:test all pass. Spec kept at `context/features/seed-spec.md`.
- Dashboard Collections: replaced the mock collection cards in the dashboard's main area with live Neon data. Added `src/lib/db/collections.ts` — `getRecentCollections()` (one query; item count via `_count`, type breakdown via a nested `items -> item -> itemType` join, so no N+1) and `getCollectionStats()` — plus `src/lib/db/user.ts` holding `getCurrentUserId()`, scoped to the seeded `demo@devstash.io` user until NextAuth lands. That helper is wrapped in React `cache()` so both fetchers share one lookup, and calls `connection()` from `next/server` before querying so Prisma results aren't baked in at build time (`export const dynamic` is on its way out in Next 16 once Cache Components is enabled); `/dashboard` now builds as `ƒ (Dynamic)`. Made `page.tsx` async and fetched both functions in a `Promise.all`; `CollectionsSection` now takes a `collections` prop instead of importing mock data. Card markup is unchanged apart from the accent colour, which is now the most-used *item type* in the collection (falling back to `defaultType`, then `--border`, for empty ones) rather than `defaultTypeId`, plus count pluralization and an empty state. Verified the rendered HTML against the seed — 5 cards with real cuid hrefs, correct counts and icon rows, and DevOps (2 links / 1 command / 1 snippet) correctly accented emerald. Build, typecheck, and lint all pass. Still mock and deliberately out of scope: the sidebar's collection lists (client component) and the Items / Favorite Items stat cards.
